# 国庆小众旅行的判断方法

## “小众”的四道筛选

1. **体验匹配**：景点是否符合用户兴趣、同行者体力和可用时间。偏僻本身没有价值。
2. **景点人流**：在目标日期/时段有无活动、预约限流、热门入口和集中打卡点。记录依据、核查时间与未知项。
3. **全程交通**：出发城至住宿、住宿至景点、景点间、返程分别检查。单一进出道路、停车容量、节假日管制、摆渡与末班车是关键瓶颈。
4. **退路可用**：堵车或人多时能否临时换线，换线是否需要新预约、是否还赶得上返程。

不要把搜索热度、评论数量、距离市中心远近当成人流统计。社媒“人少”只说明作者到访时的体验；没有日期、时段、入口和样本范围时，风险标 `unknown`。一手公告能证明规则，通常不能证明当天排队时长。路况工具的查询时间与出行日期不一致时，说明它仅是参考。

## 候选比较

每个候选用同一口径说明：适配体验、从出发地到住宿的往返代价、在当地的有效游玩时间、预算、景点人流风险、进出城和当地道路风险、最脆弱的一段、可执行的替代路线。用 `low / moderate / high / unknown` 定性；每项结论给来源和适用时间。不要输出无依据的综合分。

优先选择整段旅程更松弛的方案。有明显交通瓶颈的“冷门景点”可被近处普通但分散的路线淘汰。避拥挤和费用、早起、换宿、个人偏好冲突时，把取舍讲清，不代替用户改变锁定安排。

## 错峰与切换

先检查目标年份的国庆放假安排，再在用户可用日期内比较出发、入场和返程时段。别预设某天或某个时间“肯定不堵”。能接受早起的用户可尝试早到；不能接受就用邻近住宿、片区步行或减少跨城移动。所有时间建议都要连同营业、预约、交通时刻核查。

为关键拥堵点写 `触发条件 → 替换项目 → 新路线 → 回接点 → 时间和费用变化`。触发条件尽量是用户可观察的事实，例如停车场官方通告、导航持续显示明显超出预留时间、排队超过用户给出的上限。阈值来自用户容忍度或实际可用机动时间，不能硬编码一个适用于所有行程的数字。

## 出发前复查

交付时列出需要复查的对象和渠道：官方假期公告、预约和限流、道路管制、天气、已订交通与住宿。临近出发再查一次；当天按实时路况和现场情况选择主路线或备用路线。未来预测、实时状态、历史经验在行程中分别标明。

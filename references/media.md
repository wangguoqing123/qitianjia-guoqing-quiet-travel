# 图文攻略与轻阅读

这份指南用于基础 Markdown / HTML 交付。默认先做让人愿意看的图文攻略，再提供需要时能展开的详细资料。

## 图片怎么选

- 优先一张目的地实景封面，再为有主要游览活动的日子选择照片；交通日不必硬凑景点图。
- 用户授权照片、Wikimedia Commons 等明确许可素材可直接按许可使用。官方网页图片仍需确认使用依据；单纯“能看到”不等于已允许复用。没有合适实拍时用明确标注的示意图，不能拿附近或同名景点替代。
- 下载前核对具体城市、场馆/分馆、入口或拍摄对象；下载后实际查看图片。保存作者、原始页面、许可、拍摄时间。历史照片可以帮助认识建筑，不能用来证明今年人少、当前营业或预计天气。
- 优先使用来源提供的合适分辨率缩略图。文件放行程目录 `media/` 内，渲染时不联网；当前支持 JPEG、PNG、WebP，单张不超过 3 MB，总素材不超过 8 MB。不要把三张 5 MB 原图不加处理塞到手机攻略里。

## 数据与展示

`trip.json` 可含 `media[]`：

- `media_id`：稳定图片 ID。
- `path`：行程目录下相对路径，如 `media/museum-2016.jpg`，不接受绝对路径或越界路径。
- `place_id`：实际拍摄对象对应地点；纯装饰插画可为 null。
- `kind`：`photo` 或 `illustration`。真实景点与示意插画在图注中区分。
- `role`：`cover` 或 `place`。封面用一张 cover，place 用于照片概览与对应游览日。
- `caption`、`alt`：地点明确的图注与替代文字。
- `creator`、`source_url`、`license`、`license_url`、`taken_at`、`changes`：来源与使用说明；拍摄日期未知就 null，用户授权图片可在 license 写明授权范围。

HTML 把图片字节内嵌，单文件离线可看；Markdown 使用与行程目录相邻的图片文件，需要保留 `media/`。manifest 中登记 `kind=image` 的文件及指纹；校验检查图片文件、内嵌图片与登记的一致性。

## 先让用户看懂，再展开细节

- `itinerary.highlights[]`：每项 `{title, text}`，用少量卡片说清住宿基点、节奏与核心取舍，不写口号或方法论。
- `days[].brief`：一句话说明当天怎么玩。
- `days[].route_stop_ids[]`：当日主要地点的顺序示意；引用已有 `place_id`，明确它不是导航地图。`places[].short_name` 可提供简短标签。
- `items[].brief`：一两句实际行动；例如“上午在村里走两小段，孩子累了就提前回酒店”。
- `items[].essential_tips[]`：必须在活动旁看到的限制、未完成前提、预约或取消条件，不折叠。
- 详细行程描述、票务、地点规则、费用和来源仍同源保留，按需展开。吃饭、休息和普通转场使用紧凑行，不反复展示同一大段住宿或风险说明。
- Markdown 先放图片和速览，完整时间表和核查资料放后面；HTML 默认显示照片、路线重点、短提示与必要条件。

修改日期、地点或活动后同时核对照片与顺序示意；不能让已删除景点的照片仍冒充当天目的地。
